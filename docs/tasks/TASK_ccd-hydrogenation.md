# TASK: CCD参照構造による水素付加

> X線結晶構造解析由来の入力(通常のPDB/mmCIF)には水素座標が含まれないことが多く、ProteinDFでのDFT計算には全原子座標が必要になる。ユーザーから「X線構造など水素情報がないデータに対して、CCDを参照して水素を付加する機能が欲しい」との要望があった。詳細設計・スコープ判断(対象コンポーネント範囲、回転可能水素の扱い、プロトン化状態の扱い)はユーザーとの対話で確定済み。詳細は`RUST_PORT_SPEC.md` §3.16を参照。

## 背景

`RUST_PORT_SPEC.md` §3.16に全設計を記載済み。要点:

- 既存の`modeling.rs`(`get_ACE`/`get_NME`、Phase 6)が確立した「参照構造を`Superposer`で実構造の重原子に重ね合わせ、欠けている原子を転写する」パターンを一般化する。
- CCDの水素には2種類あり、扱いが異なる:
  1. 単一コンポーネント内で幾何が完結する水素(側鎖OH/SH/NH3+、リガンド全水素、CA-H): CCD理想配座の剛体重ね合わせで対応(PR#38)。
  2. 主鎖アミドN-H: CCD遊離アミノ酸エントリのN末端型ジオメトリとは異なるため、独立した幾何計算が必要(PR#39)。
- スコープ: 任意のCCDコンポーネント対応(リガンド含む)、回転可能水素はCCD理想配座をそのまま採用(局所最適化なし)、プロトン化状態は中性・標準タウトマー固定のみ。

**着手前に`RUST_PORT_SPEC.md` §3.16を必ず精読すること。** 本TASKファイルは実行チェックリストであり、設計判断の根拠・背景は§3.16側にある。

**PR#37レビューからの教訓(PR#38以降にも適用)**:
- 複数の値(座標のx/y/z三成分など、本来1セットとして扱うべきもの)を個別に解決・フォールバックしない。1成分でも欠ければセット全体を棄却し、次の情報源にフォールバックすること(軸ごとの独立解決は、異なる配座の値が混在した意味のない結果を生みうる)。
- 既存コード(`format/mmcif.rs`等)に類似ロジックがないか実装前に確認し、あれば共有すること。独自に再実装して重複させない。

## PR#38 レビュー結果(2026-09-24、要修正)

`feature/hydrogenation-pr38`(`rust/crates/proteindf-bridge/src/hydrogenation.rs`・`tests/test_hydrogenation.rs`新規)をClaudeが`/code-review`でレビューした。`cargo test`/`cargo clippy`/`cargo fmt`は単体では通り、正常系の実装(汎用の共有重原子マッチング・`Superposer`剛体フィット・末端残基でのカルボニルO歪み対策)は設計方針に沿っている。**ただし、マージ前に修正すべき実バグ3件と、対応推奨の副次的指摘5件が見つかった。**

### 実バグ(要修正)

1. **`Superposer`の入力が共線/縮退している場合の検証が無く、無効な回転行列が無言で返る**(`hydrogenation.rs:154`、根本原因は`superposer.rs`の`calc_rotation_matrix`、257行目付近)。
   - `calc_rotation_matrix`の行正規化ループは`if w > 0.0`のときだけ正規化し、`w`が0(またはほぼ0)の行はそのまま(ゼロベクトルのまま)残す。フィットに使う重原子が共線または近共線の場合、相関行列のランクが落ちてこの経路に入りうるが、`Superposer::new`はこれを検出せず`Ok`を返す。
   - **再現手順**: `MIN_SUPERPOSE_HEAVY_ATOMS`(3点)ちょうど、かつ3点がほぼ一直線に並ぶような`fit_heavy_atoms`を明示指定(または実構造がたまたまそうなる場合)して`add_hydrogens_to_component_in_place_with_options`を呼ぶ。エラーにならず、化学的に無意味な座標の水素が追加される。
   - これはdocコメント「3点あれば信頼性高く重ね合わせられる」(`MIN_SUPERPOSE_HEAVY_ATOMS`の説明)という主張と矛盾する。
2. **`fit_heavy_atoms`を明示指定すると、末端残基でのカルボニルO歪み対策が完全にバイパスされる**(`hydrogenation.rs:118`)。
   - 107〜111行目のコメントで説明されている重要な保護ロジック(`is_internal_peptide_residue && ccd_atom.name == "O"`のスキップ)は、`options.fit_heavy_atoms`が`Some`の場合の`else if`分岐にあり、`fit_heavy_atoms`指定時は一切評価されない。
   - **再現手順**: 鎖内(非末端)残基に対し`fit_heavy_atoms: Some(&["N","CA","C","O"])`のように"自然に見える"リストを明示指定して呼び出すと、コメントが説明する歪み(psi角に依存した約170°のずれ)がそのまま発生する。
3. **末端判定ヒューリスティックがタンパク質の原子名(OXT/N/CA/C)にハードコードされており、`RUST_PORT_SPEC.md` §3.16が要求する「固定リストではない汎用マッチング」方針、および核酸・リガンドを対象に含めるスコープと整合しない**(`hydrogenation.rs:107`)。
   - 核酸残基や、遊離カルボキシラートをモデル化していないCCDテンプレート(=`OXT`原子が無い)では、この保護が一切効かない。該当する残基種では常に対策なしの状態になり、実バグ2と同種の歪みが発生しうる。

### 副次的な指摘(必須ではないが対応推奨)

4. **`Superposer::superimpose`と同じ処理(中心を引く→回転→中心を足す)を`hydrogenation.rs:180-184`で手書きに再実装している。** これは本タスクファイルに既に記載した「PR#37レビューからの教訓」(既存ロジックとの重複禁止)の直後の再発である。既存の`superimpose`を再利用するか、再利用できない理由(戻り値の型が`AtomGroup`単位でPosition単位の変換ができない等)があるならその旨をコメントに残すこと。
5. **`pickup_atoms`(再帰的な部分木探索+`Vec`確保を伴う)を、存在確認や単一原子取得のためだけに使っている**(`hydrogenation.rs:132`の重原子マッチング、166行目の水素スキップ判定)。`component`は単一残基/リガンドのフラットな`AtomGroup`である前提なので、`get_atom`/`has_atom`(O(1)、クローンなし)で十分なはず。
6. **`is_internal_peptide_residue`(4回の`pickup_atoms`呼び出し)が、`fit_heavy_atoms`指定時(値が使われない`else if`分岐)でも無条件に計算されている**(`hydrogenation.rs:107`)。指摘2の修正と合わせて整理すること。
7. **テストコードで「残基から水素を取り除く」5行のブロックが3箇所コピペされている**(`test_hydrogenation.rs`)。共有ヘルパー化を推奨。
8. **共線/縮退フィットのケースを検証するテストが無い**(実バグ1と対)。`MIN_SUPERPOSE_HEAVY_ATOMS=3`ちょうどの境界テスト(`test_hydrogenation_insufficient_heavy_atoms_error`のCase D)はALAの実際の良条件なN/CA/C三角形を使っており、共線に近いケースはカバーされていない。

### 修正方針

- 実バグ1: `Superposer::new`(または`calc_rotation_matrix`)に、フィット点が共線/縮退している場合を検出してエラーを返すガードを追加する。修正箇所は`superposer.rs`(既存コードの根本修正、Phase 3の`get_ACE`/`get_NME`等の既存呼び出し元にも安全側の恩恵がある)と`hydrogenation.rs`(呼び出し前に独自に検証する)のどちらでもよいが、**「3点あれば信頼性高く重ね合わせられる」という主張が実際に保証される状態にすること**。判定方法(例: 相関行列のランク、フィット点がなす三角形の面積が閾値未満かどうか等)は実装時に選定し、根拠をdocコメントに残すこと。
- 実バグ2・3: 末端判定を`fit_heavy_atoms`指定の有無に関わらず一貫して適用するか、あるいは`fit_heavy_atoms`指定時は「呼び出し側が意図して選んだリストである」として保護ロジック自体を素通りさせる設計を意図的に選ぶかを判断し、その判断根拠をdocコメントに明記すること。後者を選ぶ場合でも、末端判定ヒューリスティック自体をタンパク質専用のハードコードから、§3.16が要求する汎用的な判定(例: テンプレート内の全原子のうち、実構造に存在しない原子の集合から判定する、等)に置き換えること。
