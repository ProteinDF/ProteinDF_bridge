## 背景

`RUST_PORT_SPEC.md` §9に、YUI側から以下2件が「[低・将来]」「今すぐの対応は不要」として挙げられている:
1. クレート配布方式(crates.io公開かプライベートレジストリか)の方針。YUIは現状`../ProteinDF_bridge`への相対パス依存を想定している。
2. `proteindf-bridge-py`とYUI独自の`core-py`(`yui`パッケージ)の役割分担の指針。将来的に両者が共存し得るため、どちらをいつ使うべきかのユーザー向け指針が欲しい。

いずれもコード変更は不要で、`RUST_PORT_SPEC.md` §4への追記のみで完了する。

## 対象

`RUST_PORT_SPEC.md` §4(多言語バインディング方針)に以下2点を追記すること:

1. **クレート配布方式**: 現時点ではcrates.io公開・プライベートレジストリでのバージョン管理のいずれも対応不要であること、YUI側が現状相対パス依存(`../ProteinDF_bridge`)を前提にしていることを明記する。将来これが変わる場合の判断基準(例: 外部ユーザーが増える、CI/CDでの取得が相対パスでは困難になる等)があれば触れてもよいが、必須ではない。
2. **Pythonバインディングの役割分担**: `proteindf-bridge-py`(既存`ProteinDF_bridge`のPythonユーザー向けの移行パス)と、YUI独自の`core-py`(YUI固有機能向け)の使い分け指針を追記する。どちらを使うべきかの判断基準(例: 既存Pythonコードからの移行かYUI新規機能かで使い分ける)を明記する。
